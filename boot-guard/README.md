# boot-guard

Автозащита от Insider-флайтов: задача планировщика **`Wireless-8852BE-MaxPerf`**
(от SYSTEM, триггер At Startup + 25 секунд) запускает `boot-guard.ps1`, который:

1. Сверяет драйверы всех трёх устройств (BT / WLAN / LAN) с эталонными
   версиями по `DriverProvider` + `DriverVersion`. Если флайт откатил драйвер
   на inbox-заглушку — переставляет родной из локальной распакованной копии
   (`pnputil /add-driver ... /install`), без перезагрузки.
2. Каждую загрузку заново прожимает все твики питания из соседних папок
   (MSPower, selective suspend, ASPM, роуминг, LAN advanced properties, а с v3 —
   и max-power для всех USB-контроллеров/хабов, см.
   [usb-maxpower](../usb-maxpower/)).

Лог — `boot-guard.log` рядом со скриптом, ротация на 256 КБ.

**Важно:** скрипты привязаны к локальным путям рабочей копии и конкретным
instance ID устройств. Это опубликованный снапшот рабочего сторожа, а не
универсальный инсталлятор — перед использованием поправьте пути и эталонные
версии в шапке `boot-guard.ps1`, instance ID устройств и путь к скрипту
в `register-task.ps1`.

## Файлы

- `boot-guard.ps1` — сам сторож (v3: BT + WLAN + LAN + питание всех USB).
- `register-task.ps1` — (пере)регистрация задачи планировщика + тестовый прогон.

## Почему проверка именно по DriverProvider, а не по ProblemCode

Заглушка встаёт «успешно»: ProblemCode 0, Status OK, в диспетчере всё зелёное —
при этом устройство может не работать (LAN-порт без линка). Единственный
надёжный признак подмены — провайдер драйвера перестал быть `Realtek*` или
версия опустилась ниже эталонной.
